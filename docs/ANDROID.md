# OpenH4 для Android

Нативный C++23/SDL3-порт опубликованного OpenH4. Windows EXE и DLL не используются. Исходная история и GPL-3.0 сохранены. APK экспериментальный.

## Сборка

Ветка `codex/android-arm64-import`, workflow `.github/workflows/android.yml`. GitHub Actions собирает APK и instrumentation APK, проверяет lint и запускает smoke-тест на Android 35 x86_64. Игровые ресурсы в CI не передаются. APK содержит ARM64 для телефона и x86_64 для проверки в эмуляторе.

Зафиксированы JDK 17, Gradle 8.14.3, AGP 8.10.1, SDK 36, NDK 29.0.14206865, CMake 3.31.6 и SDL release-3.4.14. Java-часть SDL берётся из того же checkout, что и нативная библиотека. Нужен Android 11 или новее.

Для локальной сборки установите эти SDK-пакеты, задайте `ANDROID_HOME`, `JAVA_HOME`, `GRADLE_USER_HOME` на диске с достаточным местом, получите SDL:

```sh
git clone --depth 1 --branch release-3.4.14 https://github.com/libsdl-org/SDL.git /your/external/disk/SDL
export SDL3_SOURCE_DIR=/your/external/disk/SDL
gradle -p android --no-daemon --max-workers=2 assembleDebug assembleDebugAndroidTest lintDebug
```

Для проверки плавности устанавливайте оптимизированный Release, а не Debug:

```sh
gradle -p android --no-daemon --max-workers=2 -PtestBuildType=release assembleRelease assembleReleaseAndroidTest lintRelease
```

Файл установки: `android/app/build/outputs/apk/release/app-release.apk`. В нативной части это `RelWithDebInfo` с `-O2 -g -DNDEBUG`. Не менялись проверки входных данных, `expected`/обработка ошибок, защита стека и FORTIFY. `assert` в игровом коде не используется. Debug остается отдельным диагностическим вариантом с эффективным `-O0` и прежним сертификатом. Начиная с боевого этапа, CI использует постоянный PKCS12-ключ из GitHub Actions secrets `OPENH4_KEYSTORE_BASE64` и `OPENH4_KEYSTORE_PASSWORD`. Workflow прекращает сборку без ключа и проверяет публичный SHA-256 сертификата из `android/signing-certificate.sha256`. Ключ, пароли и коммерческие игровые файлы не входят в Git или artifacts.

Для локальной сборки тем же ключом задайте `OPENH4_KEYSTORE` с путем к защищенному PKCS12 и `OPENH4_KEYSTORE_PASSWORD` из своего хранилища секретов. Без этих переменных локальная debug-сборка использует обычный локальный ключ Android и не сможет обновить подписанную CI-версию.

Исходная APK `e49f3be` подписана другим временным ключом, который невозможно восстановить из APK. Она сохранена отдельно. Для перехода с нее на постоянный ключ может потребоваться один раз удалить приложение и повторить импорт. Исходная папка ресурсов при удалении приложения не меняется. Дальнейшие обновления с новым постоянным ключом проверены через `adb install -r` без удаления 114 импортированных файлов.

## Ресурсы и импорт

Скопируйте на телефон корневую папку своей игры:

```text
HeroesIV/
  data/
    heroes4.h4r
    text.h4r
    updates.h4r
    music.h4r
    movies.h4r
    storm.h4r
    storm_override.h4r
    x2.h4r
    x2_override.h4r
  maps/
    scenario.h4c
```

Обязателен `heroes4.h4r`; остальные архивы зависят от издания. Для Complete сохраняйте все штатные H4R. Поддерживаются также штатные `new.h4r`, `storm_updates.h4r`, `x2_updates.h4r` и названия override/updates с пробелами, как в исходном загрузчике. Не добавляйте неизвестные моды. Исходная игра не изменяется, EXE/DLL, Wine и моды не копируются.

Откройте OpenH4, нажмите «Импортировать папку», выберите корень HeroesIV через системное окно и подтвердите доступ. `Data`/`Maps` допускаются с любым регистром. Внутри приложения имена H4R приводятся к нижнему регистру, имена карт сохраняются. Папку Data отдельно выбирать нельзя. Служебные AppleDouble и конфликтующие дубликаты не импортируются.

Импорт идёт в приватную временную папку. Нативный код проверяет каталоги H4R, загружает таблицы правил и строит оригинальное меню. Только после успеха новая папка заменяет предыдущий импорт. При прерывании переноса предыдущая установка восстанавливается. Нужно место на телефонную копию и на предыдущий импорт до завершения замены.

`org.openh4.android` не запрашивает сетевые разрешения и не отправляет ресурсы. Основной SDL-движок работает в процессе `:game`. Настройки и импорт находятся в приватной памяти приложения. Удаление приложения удалит эти данные, а исходная папка на телефоне сохранится.

## Что проверить на устройстве

1. Установку и открытие импортера, отказ от некорректного H4R.
2. Выбор папки через SAF, нативную проверку базы правил и меню.
3. Оригинальное меню, сценарии, загрузку карты, перемещение армии и доступные взаимодействия.
4. Разворачивание Fold, смену размера окна, касания и перетаскивание.

SDL переводит касания в события мыши. Отдельные жесты удержания и масштабирования карты пока не реализованы. Android Back передаётся как Escape. Изображение сохраняет пропорции; полноценная переработка интерфейса для Fold не выполнена.

## Ограничения движка

Реализован базовый рукопашный бой: столкновение враждебных армий, размещение до семи отрядов на сторону, очередь по скорости, перемещение, атака с одновременным ответом, потери, победа/поражение/взаимная гибель и возврат на карту. Количество существ, HP выживших, погибшие герои и удаление побежденной армии переносятся в состояние приключения. Опыт получают только выжившие герои победителя.

Это ограниченная модель: поле 12 x 9 крупных квадратных клеток, движение существ пересчитано в эти клетки, урон детерминирован по середине диапазона и базовым Attack/Defense. Используются оригинальные характеристики существ и портреты; формулы героев взяты из существующего интерфейса движка. Стрельба, заклинания, мораль, удача, особые способности, тактика, препятствия/осады, добыча и воскрешение героев пока отсутствуют. Изображение отряда является портретом, анимации боя не реализованы. Противник только сближается и атакует в рукопашную.

Полноценного ИИ карты, сохранения/загрузки партии и звукового backend нет. Часть действий карты и развития героев по-прежнему помечены `not_ported`. Закрытие игрового процесса теряет несохраненную партию; оригинальные файлы не изменяются. Следующий этап - сохранение состояния партии с потерями, ранениями, опытом и удаленными армиями.

Тексты и bitmap-шрифты читаются из исходных H4R без принудительного UTF-8 преобразования. Поддержка конкретной русской редакции требует проверки её ресурсов и снимков на устройстве; английские ресурсы не переводятся автоматически.

## Диагностика

`adb logcat` содержит теги `OpenH4`, `SDL` и вывод нативного движка. Журнал импорта доступен в debug-сборке:

```sh
adb shell run-as org.openh4.android cat files/import.log
```

Smoke-тест проверяет настоящий нативный parser на усеченном H4R, фильтрацию файлов и `combatSelfTest()` с теми же C++ тестами, что и локальный `h4-combat-tests`. Проверяются численный урон и ответ, очередность/раунды, путь/блокировки/бюджет движения, гибель, ничья, потери/ранения и опыт, отказ от повторного применения результата, неверного владельца и дистанции. Оригинальных ресурсов в CI нет; smoke не заменяет полный тест игрового интерфейса. Скриншот импортера и logcat сохраняются как Actions artifact.

Локальная проверка без коммерческих fixtures:

```sh
cmake -S . -B /your/external/disk/build -DH4_BUILD_PLATFORM=OFF
cmake --build /your/external/disk/build --target h4-combat-tests
/your/external/disk/build/tests/h4-combat-tests
```

Контроль с собственными ресурсами через настоящие контроллеры карты и боевого экрана:

```sh
cmake --build /your/external/disk/build --target h4-encounter-test
/your/external/disk/build/tests/h4-encounter-test /your/game/data "/your/game/maps/Jester's Revenge.h4c" /your/private/test-output
```

Этот тест загружает оригинальную карту, проходит к ближайшему нейтралу и управляет боем через события того же интерфейса. Герой остается сзади; существа сближаются и атакуют. Он проверяет возвращенные потери, удаление армий и опыт выжившего героя. Снимки содержат оригинальную графику и должны оставаться локально.

На Android: дважды выберите доступную враждебную армию на карте. В бою золотая рамка отмечает активный отряд; касание клетки или соседнего врага выбирает действие, `Confirm` подтверждает. После перемещения можно атаковать, если цель рядом; `End turn` завершает ход. `Surrender...` требует подтверждения и уничтожает эту армию. После конца боя `Return to map` применяет результат. Подробный проверенный сценарий приведен в `docs/STATUS-RU.md`.

## Диагностика производительности

Android-версия пишет сводку `openh4.perf` в SDL logcat примерно раз в пять секунд. В ней есть FPS, median/p95/p99/max длительности кадра, время ввода/изменения размера, обновления игры, отрисовки всей сцены, карты, ландшафта, объектов, тумана войны, остального интерфейса, передачи текстуры, RenderPresent и работы контроллера после кадра. Время RenderPresent включает ожидание VSync и не является чистым временем GPU.

`process_cpu_percent` складывает CPU всех потоков игрового процесса; 100% соответствует одному занятому логическому CPU и значение может превышать 100%. `peak_rss_kib` - пиковая резидентная память процесса, а не PSS и не сумма памяти всего приложения/драйвера. Исходные игровые архивы и содержимое ресурсов в сводку не попадают.

В CI используется отдельный внутренний тестовый запуск на процедурных ресурсах: настоящий цикл Application, экран меню, MapRenderer и BattleView. Он обходит импорт только для бенчмарка и не доступен из обычного пользовательского лаунчера. Скрипт ограничен GitHub Actions и выделенным x86_64-эмулятором. Android-файлы пользователя для него не нужны. Подробная методика и результаты приведены в PERFORMANCE-RU.md.
